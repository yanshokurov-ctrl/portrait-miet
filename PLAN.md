## 1. Исходные данные

- **Цель:** программный модуль, который определяет личностные характеристики человека по методически подготовленным вопросам и ключам. В дальнейшем модуль интегрируют в систему построения индивидуальной образовательной траектории.
- Каждая команда проходит все три этапа и делает модуль целиком: движок опроса, сборщик результатов, 20 методик, интерфейс, валидатор, тесты, документацию.
- **Актуально 20 методик.** Упоминания «9 спектров», «пар команд», «Команды 21» и «23 команд» в заданиях — остатки старой версии, их не учитываем.
- Вопросы и ключи выдадут позже (база данных). Ядро не должно зависеть от того, откуда берутся вопросы.
- В итоге к модулю подключат обёртку для тестирования. Внешний интерфейс модуля должен быть стабильным и описанным.
- **Технологии:** Python 3.11+, только стандартная библиотека; комментарии на русском.

## 3. Архитектура

```
portrait/
  core/
    models.py       # Question, Answer, MethodResult, Portrait (dataclasses)
    contracts.py    # интерфейс методики MethodBlock (ABC) + справочник METHODS
    engine.py       # «Движок опроса»
    collector.py    # «Сборщик результатов»
    errors.py       # свои исключения
  sources/
    base.py         # QuestionSource — абстракция источника вопросов
    json_source.py  # временный источник (JSON), потом db_source.py
  methods/
    scoring.py      # общий подсчёт по ключам
    data/m01.json … m20.json   # вопросы, ключи, нормы, тексты интерпретаций
  validator/        # этап 3
  ui/
    console.py      # прототип
    gui.py          # tkinter, этап 3
  tests/
  docs/
  main.py
```

**Путь данных:** источник вопросов → движок опроса → методики (`process`) → сборщик → «Портрет личности» → интерфейс / экспорт.

### Контракт методики

```python
class MethodBlock(ABC):
    id: str            # "m01"
    name: str          # "Оценка особенностей личности"

    @abstractmethod
    def get_questions(self) -> list[Question]: ...

    @abstractmethod
    def process(self, answers: dict[str, Answer | None]) -> MethodResult: ...
```

`MethodResult`: `method_id`, `method_name`, `status` (`ok` / `partial` / `error` / `no_data`), `scores` (шкала, сырой балл, уровень), `interpretation`, `answered`, `total`, `errors`.

### Методики описываются данными

Каждая методика — JSON-файл: вопросы, ключи, обратные пункты, подшкалы, пороги уровней «низкий / средний / высокий», тексты интерпретаций. Подсчёт делает общий `scoring.py` с 3–4 типами:

- сумма баллов по ключу;
- сумма с обратными пунктами;
- подсчёт правильных ответов (тесты вроде «Когнитивной рефлексии»);
- выбор категории (вроде «Когнитивных стилей»).

Без этого 20 методик не уложить в этап 2 — на него всего 4 занятия.

### Обработка ошибок

- Движок вызывает каждую методику через `try/except`: упавшая методика получает `status="error"`, опрос продолжается.
- Сборщик проверяет формат каждого результата.
- В отчёте всегда 20 позиций: отсутствующие помечаются, данные не теряются и не дублируются.
