# Контракт методики

Этот документ описывает, как устроена любая методика модуля и как она общается с движком опроса.
Код контракта — [portrait/core/contracts.py](../portrait/core/contracts.py), модели данных — [portrait/core/models.py](../portrait/core/models.py).

## Как это работает

```
Источник вопросов ──► Движок опроса ──► Методика.process() ──► Сборщик ──► «Портрет личности»
                         │    ▲
     get_questions() ────┘    └──── ответы пользователя
```

1. Движок получает от каждой методики список вопросов: `get_questions()`.
2. Движок показывает вопросы пользователю и собирает ответы.
3. Движок передаёт каждой методике её ответы: `process(answers)`.
4. Методика считает баллы и возвращает `MethodResult`.
5. Сборщик объединяет результаты всех 20 методик в `Portrait`.

Движок ничего не знает о том, как методика считает баллы. Методика ничего не знает о том, как показываются вопросы.

## Справочник методик

`METHODS` в `contracts.py` — официальный список 20 методик: id → название. Порядок в справочнике — порядок прохождения опроса.

| id | Методика | id | Методика |
|---|---|---|---|
| m01 | Оценка особенностей личности | m11 | ПОАК |
| m02 | Индекс устойчивости идентичности | m12 | Мотивация учебной деятельности |
| m03 | Критическое мышление | m13 | СЖО |
| m04 | Когнитивная рефлексия | m14 | Стили коммуникации |
| m05 | Когнитивные стили | m15 | Тест-опросник критического мышления (КМ) |
| m06 | Методика СОРЕ | m16 | Потребность в познании |
| m07 | Методика измерения альтруистических установок | m17 | Формально-динамические свойства индивидуальности (темперамент) |
| m08 | Метакогнитивная включенность в деятельность | m18 | Фундаментальные свойства личности |
| m09 | Методика СО | m19 | Черты характера |
| m10 | Методика СПД | m20 | Эмоциональный интеллект |

## Класс MethodBlock

```python
class MethodBlock(ABC):
    id: str     # id из справочника, например "m16"
    name: str   # название из справочника

    def get_questions(self) -> list[Question]: ...
    def process(self, answers: MethodAnswers) -> MethodResult: ...
```

### Правила

1. `id` и `name` берутся из справочника `METHODS`.
2. `get_questions()` возвращает все вопросы методики:
   - у каждого вопроса `method_id` равен `id` методики;
   - `id` вопросов не повторяются и имеют вид `m16_q01`, `m16_q02`, …;
   - `order` идёт по порядку: 1, 2, 3, …
3. `process(answers)` получает словарь, где есть **все** id вопросов методики. Значение — одно из трёх:

   | Значение | Что значит |
   |---|---|
   | `Answer("m16_q01", 3)` | Пользователь ответил |
   | `Answer.skip("m16_q01")` | Пользователь отказался отвечать |
   | `None` | Пользователь до вопроса не дошёл (остановил опрос) |

4. `process(answers)` возвращает `MethodResult`, где `method_id` и `method_name` совпадают с методикой, `answered` — сколько вопросов отвечено, `total` — сколько всего вопросов.
5. **Пропуски — не ошибка.** `process` не должен из-за них падать; он возвращает статус `partial` или `no_data`. Какой именно — решает общее правило `result_status(answered, total)` из `contracts.py`: всё отвечено — `ok`, не меньше 50% — `partial`, меньше — `no_data` (подробнее — [errors.md](errors.md)). Если `process` всё же выбросит исключение, движок поймает его и поставит методике статус `error`, остальные методики продолжат работу.
6. Методика не хранит состояние между вызовами: повторный вызов `process` с теми же ответами даёт тот же результат.

## Модели данных

### Question — вопрос

| Поле | Тип | Описание |
|---|---|---|
| `id` | str | `"m16_q01"` — начинается с id методики и `_` |
| `method_id` | str | `"m16"` |
| `text` | str | Текст вопроса |
| `order` | int | Номер внутри методики, с 1 |
| `type` | QuestionType | `choice`, `scale`, `number` или `text` |
| `options` | list[Option] | Варианты ответа: `Option(value, label)`. Нужны для `choice` и `scale`, для `number` и `text` — пусто |

Типы вопросов:

| Тип | Допустимый ответ | Пример |
|---|---|---|
| `choice` | Одно из значений `options` | «а», «б», «в» |
| `scale` | Одно из значений `options` | 1–5 «совсем не согласен … полностью согласен» |
| `number` | Любое число | Задачи на когнитивную рефлексию |
| `text` | Непустая строка | Свободный ответ |

Проверить ответ: `question.is_valid_value(value)`.

### Answer — ответ

| Поле | Тип | Описание |
|---|---|---|
| `question_id` | str | id вопроса |
| `value` | int / float / str / None | Значение ответа; `None` только у пропущенного |
| `skipped` | bool | `True`, если пользователь отказался отвечать |

### MethodResult — результат методики

| Поле | Тип | Описание |
|---|---|---|
| `method_id`, `method_name` | str | Какая методика |
| `status` | Status | См. таблицу статусов |
| `scores` | list[ScaleScore] | Баллы по шкалам: `ScaleScore(scale, raw, level)`. Обязательны для `ok` и `partial` |
| `interpretation` | str | Текстовый вывод для пользователя |
| `answered` | int | Сколько вопросов отвечено |
| `total` | int | Сколько вопросов в методике |
| `errors` | list[str] | Описание проблем; для `error` и `no_data` — причина |

Статусы:

| Статус | Когда |
|---|---|
| `ok` | Все вопросы отвечены, результат посчитан |
| `partial` | Часть вопросов пропущена, результат посчитан с оговоркой |
| `error` | Методика упала или вернула результат в неверном формате |
| `no_data` | Результата нет: слишком много пропусков или методика ничего не прислала |

Готовые конструкторы: `MethodResult.error(id, name, "причина")` и `MethodResult.no_data(id, name, "причина")`.

### Portrait — итоговый отчёт

| Поле | Тип | Описание |
|---|---|---|
| `respondent_id` | str | Анонимный id того, кто проходил опрос |
| `created_at` | str | Дата и время формирования, ISO |
| `results` | list[MethodResult] | Результаты методик в порядке прохождения |
| `warnings` | list[str] | Предупреждения сборщика |

Методы: `get(method_id)`, `summary()` — сколько методик в каждом статусе, `to_json()` / `from_json()`.

Все модели проверяют свои данные при создании и при ошибке выбрасывают `ValueError` с понятным сообщением.

## Пример методики

Полный рабочий пример — класс `DemoMethod` в [tests/test_contracts.py](../tests/test_contracts.py).

```python
class DemoMethod(MethodBlock):
    id = "m16"
    name = METHODS["m16"]

    def get_questions(self) -> list[Question]:
        options = [Option(1, "Не согласен"), Option(2, "Затрудняюсь"), Option(3, "Согласен")]
        return [
            Question(id="m16_q01", method_id="m16", text="Мне нравится разбираться в сложных задачах",
                     order=1, type=QuestionType.SCALE, options=options),
            # ...
        ]

    def process(self, answers: MethodAnswers) -> MethodResult:
        total = len(answers)
        values = [a.value for a in answers.values() if a is not None and not a.skipped]
        if not values:
            return MethodResult.no_data(self.id, self.name, "Нет ни одного ответа", total=total)

        raw = sum(values)
        level = "высокий" if raw >= 7 else "средний" if raw >= 5 else "низкий"
        return MethodResult(
            method_id=self.id, method_name=self.name,
            status=Status.OK if len(values) == total else Status.PARTIAL,
            scores=[ScaleScore("Потребность в познании", raw, level)],
            interpretation=f"Уровень потребности в познании: {level}",
            answered=len(values), total=total,
        )
```
