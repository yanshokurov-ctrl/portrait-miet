## 1. `docs/architecture.md` — как устроен модуль

**Читатели:** преподаватель, новые участники, команда этапа 3. **Объём:** 2–3 страницы.

### 1.1. Назначение
- [ ] 2–3 предложения: модуль определяет личностные характеристики по 20 методикам; это первая часть системы из ТЗ (дальше — база ответов, матрица шкал, статистика, нейросеть).

### 1.2. Схема работы
- [ ] Схема:
  ```
  JSON-файлы методик → Источник вопросов → Движок опроса ⇄ Интерфейс (консоль)
                                                ↓ ответы
                                            Методики (подсчёт по ключам)
                                                ↓ результаты
                                            Сборщик → «Портрет личности» → экран + portrait.json
  ```
- [ ] Под схемой — по одной фразе на каждую стрелку: что передаётся (вопросы, ответы, результаты, отчёт).

### 1.3. Части модуля
- [ ] Таблица «часть → файл → что делает»:

  | Часть | Файл |
  |---|---|
  | Модели данных | `portrait/core/models.py` |
  | Контракт методики, справочник 20 методик | `portrait/core/contracts.py` |
  | Движок опроса | `portrait/core/engine.py` |
  | Сборщик результатов | `portrait/core/collector.py` |
  | Исключения | `portrait/core/errors.py` |
  | Источник вопросов | `portrait/sources/base.py`, `portrait/sources/json_source.py` |
  | Методика из JSON и подсчёт по ключам | `portrait/methods/json_method.py`, `portrait/methods/scoring.py` |
  | Данные методик | `portrait/methods/data/m01.json … m20.json` |
  | Интерфейс | `portrait/ui/console.py`, `main.py` |

### 1.4. Принципы
По абзацу на каждый — с объяснением, зачем так сделано:
- [ ] Движок не знает о конкретных методиках — работает с любой через контракт `MethodBlock`.
- [ ] Методики описаны данными (JSON), а не кодом — новая методика или правка ключа не требует программирования.
- [ ] Источник вопросов заменяемый — для базы данных преподавателя достаточно написать новый `QuestionSource`, ядро не меняется.
- [ ] Сбой одной методики не ломает опрос — она получает статус `error`, остальные считаются.
- [ ] Требования ТЗ: название методики респонденту не показывается; завершить опрос можно только после всех методик.

### 1.5. Структура репозитория
- [ ] Дерево папок с комментариями (взять из README).
- [ ] Отдельно: где тесты (`tests/`) и тестовые методики (`tests/fixtures/methods`).

### 1.6. Ссылки
- [ ] На `contract.md`, `method_format.md`, `errors.md`, `api.md`.

**Источники:** docstring в начале каждого файла из таблицы, `docs/contract.md`, `README.md`.

## 2. `docs/api.md` — функции модуля

**Читатели:** команда интерфейса и валидатора (этап 3), обёртка преподавателя для тестирования. **Главный документ этапа.** **Объём:** 4–6 страниц.

**Формат описания каждой функции:**
```
### answer(value)
Что делает: …
Параметры: value — …
Возвращает: …
Ошибки: InvalidAnswerError — …; SessionError — …
Пример: session.answer(3)
```

### 2.1. Быстрый старт
- [ ] Полный путь в 10–15 строк кода: загрузка → опрос → отчёт → сохранение. Образец — функция `run()` в `portrait/ui/console.py`.
- [ ] **Пример обязательно запустить** и убедиться, что он работает.

### 2.2. Источник вопросов
- [ ] `JsonSource(папка)` — без параметра берётся `portrait/methods/data`.
- [ ] `load_methods()` → список методик в порядке справочника.
- [ ] Ошибки `SourceError`: папка не найдена; файл не читается (в сообщении — имя файла); одна методика в двух файлах.

### 2.3. Движок `SurveySession`
- [ ] **Создание:** `SurveySession(методики)`. `SessionError` — нет методик, методики нет в справочнике, методика передана дважды. Методика, у которой не получилось взять вопросы, опрос не останавливает — в итоге получит `error`.
- [ ] **Состояние:**
  - `current_question()` — текущий вопрос или `None`, если вопросы кончились;
  - `current_answer()` — прежний ответ (при возврате назад);
  - `current_method()` — текущая методика;
  - `progress()` — номер вопроса, всего вопросов, сколько отвечено;
  - `method_progress()` — номер методики, всего методик, номер вопроса внутри методики, вопросов в ней;
  - `is_finished()` — все ли вопросы пройдены.
- [ ] **Действия:**
  - `answer(value)` — проверить ответ и перейти дальше. `InvalidAnswerError` — ответ не подходит (в тексте — допустимые варианты); `SessionError` — вопросы кончились;
  - `back()` — к предыдущему вопросу; `SessionError` на первом вопросе.
- [ ] **Дополнительно:** `next()`, `skip()` — отметить, что в консоли **не используются**: респондент обязан ответить на каждый вопрос.
- [ ] **Итог:** `grouped_answers()` — ответы по методикам; `finish()` — результаты всех методик (`MethodResult`).

### 2.4. Сборщик
- [ ] `collect(результаты, respondent_id=None)` → `Portrait`; без id создаётся анонимный вида `anon-1a2b3c4d`.
- [ ] `to_text(портрет)` — текстовый отчёт.
- [ ] `validate_result(результат)` — проверка формата, `InvalidResultError` (пригодится валидатору на этапе 3).

### 2.5. Модели
Коротко, подробности — ссылкой на `contract.md`:
- [ ] `Question.is_valid_value()`.
- [ ] `Portrait`: `get()`, `summary()`, `to_json()`, `from_json()`.
- [ ] Статусы `Status` и правило `result_status()` (порог 50%).

### 2.6. Исключения
- [ ] Таблица «исключение → когда → выходит ли наружу». Сослаться на `errors.md`, не дублировать.

### 2.7. Командная строка
- [ ] `python main.py`, параметры `--data`, `--out`, `--respondent`.
- [ ] Коды завершения: `0` — успешно; `1` — ошибка загрузки, опрос прерван или не удалось сохранить файл.

**Источники:** docstring функций (в них описано поведение и ошибки), `README.md`.

## 3. `docs/portrait_format.md` — формат итогового отчёта

**Читатели:** команда экрана результатов, психологи, преподаватель. **Объём:** 2–3 страницы.

### 3.1. Что это
- [ ] Отчёт по всем 20 методикам; выводится на экран и сохраняется в `portrait.json`.

### 3.2. Поля верхнего уровня
- [ ] Таблица «поле → тип → описание»: `respondent_id`, `created_at`, `summary` (сколько методик в каждом статусе), `results`, `warnings`.

### 3.3. Результат методики
- [ ] Поля: `method_id`, `method_name`, `status`, `scores` (шкала, балл, уровень — уровни сейчас пустые: в исходных документах нет норм), `interpretation`, `answered`, `total`, `errors`.

### 3.4. Статусы
- [ ] Таблица:

  | Статус | Когда |
  |---|---|
  | `ok` | Отвечено всё |
  | `partial` | Отвечено не меньше 50% |
  | `no_data` | Отвечено меньше 50% или результата нет |
  | `error` | Методика упала или вернула неверный формат |

### 3.5. Правила сборщика
- [ ] Всегда 20 методик в порядке справочника.
- [ ] Повторный результат — оставляется первый + предупреждение.
- [ ] Неизвестная методика — отбрасывается + предупреждение.
- [ ] Неверный формат → `error`.
- [ ] Нет результата → `no_data` «Результат не получен».

### 3.6. Примеры JSON
Настоящие, из запуска; сократить до 2–3 методик, остальное — `…`:
- [ ] всё пройдено;
- [ ] есть методики без результата (в коротком опросе — методики 4–20);
- [ ] методика упала (пример — в `tests/test_collector.py`).

### 3.7. Текстовый вид
- [ ] Копия того, что печатает консоль после опроса.

**Источники:** `portrait/core/models.py`, `portrait/core/collector.py`, реальный `пример.json`.

## 4. `docs/scenarios.md` — сценарии прохождения опроса

**Читатели:** тестировщики, преподаватель; основа для руководства пользователя на этапе 3. **Объём:** 3–4 страницы.

**Формат каждого сценария:** цель → шаги (что вводит пользователь) → что видит (фрагмент консоли) → результат.

- [ ] **1. Полное прохождение:** запуск → «Методика 1 из N» и инструкция → «Вопрос 1 из 3 (всего: 1 из 9)» → ответы → «Все методики пройдены» → `з` → отчёт и «Результат сохранён в файл…».
- [ ] **2. Неверный ответ:** `7` или `абв` → «! Введите номер варианта от 1 до 3» → тот же вопрос снова.
- [ ] **3. Возврат назад:** `н` → «Ваш прежний ответ: … — введите ответ заново» → новый ответ.
- [ ] **4. Назад с первого вопроса:** «! Вы уже находитесь на первом вопросе».
- [ ] **5. Завершить раньше времени:** `з` → «! Завершить опрос можно только после того, как пройдены все методики».
- [ ] **6. Возврат с последнего экрана:** `н` → последний вопрос.
- [ ] **7. Прерывание:** Ctrl+C → «Опрос прерван», результат не сохраняется, код 1.
- [ ] **8. Нет методик:** `python main.py --data нет_такой_папки` → «Не удалось загрузить методики: …», код 1.
- [ ] В конце — таблица команд (`н`, `з`, `?`) и пометка: **пропустить вопрос нельзя**.

**Источники:** запуск программы; `tests/test_console.py` — там проверяются те же сценарии.

## Как делать примеры

Короткий опрос на тестовых методиках (3 методики по 3 вопроса):

```bash
python main.py --data tests/fixtures/methods --out пример.json
```

Ответы по очереди: `1`, `2`, `3`, `1`, `4`, `3`, `2`, `1`, любой текст, затем `з`.
