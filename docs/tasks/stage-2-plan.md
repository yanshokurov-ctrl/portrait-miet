## Шаг 2. Общие правила — утвердить в команде

**Кто:** основной разработчик + вся команда (10 минут на занятии).

- [ ] **Округление:** среднее (методика 12) — до 2 знаков.
- [ ] **Пропуски:** в консоли пропуск отключён — ответ обязателен. Порог 50% (`MIN_ANSWERED_SHARE`) остаётся для будущих интерфейсов.
- [ ] **Значение ответа = балл:** подписи вариантов — как в бланке, значение — балл (например, методика 7: подписи «−3…3», баллы 0…6).

## Шаг 4. Интерпретация: баллы → текстовые выводы

**Кто:** основной разработчик — механизм; разработчики — тексты.

### 4а. Сейчас, без норм
- [ ] Для каждой шкалы автоматически считать диапазон по вариантам ответа и пунктам: «Самооценка: 12 (возможно от 4 до 20)».
- [ ] Вывод в отчёте: балл, диапазон, пометка «нормы не заданы».

### 4б. Когда будут нормы
- [ ] Поле `levels` у шкалы в JSON: `[{"max": 8, "level": "низкий", "text": "…"}, …]`.
- [ ] Подсчёт ставит уровень (`ScaleScore.level`) и текст вывода.
- [ ] Разработчики пишут тексты для уровней «низкий / средний / высокий» — по 6–7 методик на человека.

## Шаг 5. Тестирование методик

**Кто:** тестировщики, методики делятся поровну.

Для каждой методики:
- [ ] **Ручной расчёт:** 2 набора ответов → посчитать баллы вручную по ключу из документа → сверить с программой.
- [ ] **Граничные случаи:** все ответы минимальные и все максимальные → баллы совпадают с диапазонами из документа.
- [ ] **Некорректные данные:** неверный ответ в консоли; испорченный JSON методики (неверный номер в ключе, нет варианта ответа) → программа не запускается и показывает понятное сообщение.
- [ ] Расхождения — баг-репортом основному разработчику: методика, ответы, ожидалось, получено.

Подсказка: в `tests/test_methods_data.py` есть проверенные примеры для каждой методики — с ними можно сверяться.
